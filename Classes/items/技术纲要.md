# 泰拉瑞亚风格：物品与合成系统技术纲要

## 1. 核心架构理念 (Core Concepts)

* **数据驱动 (Data-Driven)**
    * 所有的物品属性、合成配方均由 JSON 文件定义。
    * 代码只负责逻辑解析，绝不硬编码数据。
* **分离设计 (Separation)**
    * **定义 (Definition)**: 物品长什么样、叫什么（只读数据，单例管理）。
    * **实例 (Instance)**: 背包里那一格具体的物品（数量、词缀，动态数据）。
* **被动响应 (Reactive)**
    * UI 不进行每帧轮询 (Polling)，只有在“数据变动”或“环境变动”时才触发刷新 (Event-based)。

## 2. 物品系统 (Item System)
> **注**：这是合成系统的基石，必须先于合成系统完成。

### 2.1 数据层：物品定义 (Item Definition)
* **存储方式**: `items.json`
* **加载方式**: 游戏启动时一次性加载到 `ItemManager` 单例中。
* **核心字段**:
    * `ID` (int): 唯一标识符。
    * `Name` (string): 显示名称。
    * `Type` (enum): 武器、工具、材料、消耗品、放置物。
    * `MaxStack` (int): 最大堆叠数（如材料999，武器1）。
    * `IconPath` (string): 图片资源路径。
    * `Value` (int): 售价。
    * `Tags/Groups` (list): 属于哪些组（如“木材”、“铁锭”），用于合成时的模糊匹配。

### 2.2 运行层：物品实例 (Item Instance / Slot)
* **概念**: 背包里实际存储的对象。
* **数据结构**:
    ```cpp
    struct InventorySlot {
        int itemId;     // 引用 ID，为 0 时表示空格
        int count;      // 当前数量
        int prefixId;   // (进阶) 词缀/附魔 ID，如 "传说中的", "破碎的"
    };
    ```

### 2.3 管理层：ItemManager
* **职责**:
    1.  提供 `getItemData(int id)` 方法，通过 ID 查属性（只读）。
    2.  提供 `getItemSprite(int id)` 方法，快速获取 SpriteFrame。

## 3. 背包系统 (Inventory System)
> **注**：它是物品与合成的中间桥梁。

### 3.1 数据结构
* **容器**: `std::vector<InventorySlot> slots`
* **容量**: 固定大小（如 50 格）。

### 3.2 核心功能 API
* `bool AddItem(int id, int count)`: 自动堆叠、自动找空格。返回是否成功（处理捡起掉落物）。
* `bool RemoveItem(int id, int count)`: 简单扣除（用于丢弃物品或消耗材料）。
* `int GetItemCount(int id)`: 查询背包里某物品的总数（用于合成检查）。
* **事件通知**: 当背包发生任何变动时，发送 `Event_InventoryChanged`，通知 UI 和合成系统刷新。

## 4. 合成系统 (Crafting System)
> **核心逻辑**：基于“邻近环境”判定，而非必须打开工作台界面。

### 4.1 数据层：配方定义 (Recipe Definition)
* **存储方式**: `recipes.json`
* **核心字段**:
    * `Result`: 产物 (Item ID + Count)。
    * `Station` (Enum): 需要的环境（徒手/工作台/熔炉/铁砧）。
    * `Ingredients` (List):
        * `Type`: 是指定物品 ID，还是配方组 ID。
        * `ID`: 对应的数值。
        * `Count`: 消耗数量。

### 4.2 逻辑层：环境检测 (Context Detection)
* **触发时机**: 玩家移动时、进入/离开特定区域时。
* **实现逻辑**:
    1.  玩家身上挂一个矩形检测框 (`Rect`)。
    2.  检测地图图块 (`TileMap Layer`) 或 家具实体 (`Entity`)。
    3.  维护一个 `std::vector<StationType> currentStations` 列表。
    4.  **特性**: 列表始终包含 `StationType::None` (代表徒手合成)。

### 4.3 核心算法：配方匹配 (The Matcher)
* **输入**: `PlayerInventory` + `CurrentStations`
* **流程**:
    1.  **环境初筛**: 过滤掉所有不需要当前环境的配方。
    2.  **缓存背包**: 建立 `Map<ItemID, TotalCount>` 快照，加速查询。
    3.  **材料比对**: 遍历配方需求，检查 Map 中是否有足够数量。支持“配方组”递归查找。
    4.  **输出**: 生成 `AvailableRecipes` 列表。

### 4.4 执行层：合成制造 (The Crafter)
* **输入**: 选中的 `Recipe` 对象。
* **流程**:
    1.  **二次校验**: 防止手速过快/网络延迟导致的资源不同步。
    2.  **贪婪扣除**: 遍历背包，优先扣除靠前的格子，直到扣满所需数量。
    3.  **产物发放**: 调用 `Inventory.AddItem`。
    4.  **溢出处理**: 如果背包满了，生成 `DropItem` 实体在玩家脚下。
    5.  **回调刷新**: 触发 `Event_InventoryChanged`，强制刷新合成列表。

## 5. UI 交互层 (User Interface)

### 5.1 布局设计
* **左侧/主区域**: 背包网格 (Inventory Grid)。
* **特定区域 (如左下)**: 合成列表 (Crafting Strip/List)。
    * *泰拉瑞亚特色*: 这是一个垂直滚动的长条，当前选中项会放大显示。

### 5.2 交互逻辑
* **实时刷新**: 监听 `Event_InventoryChanged` 和 `Event_StationUpdate`。
* **点击合成**:
    * **点击图标**: 只是选中，显示所需材料详情。
    * **再次点击/长按**: 执行合成逻辑。
    * **优化**: 长按时，每隔 0.2秒 执行一次合成（批量制作）。
